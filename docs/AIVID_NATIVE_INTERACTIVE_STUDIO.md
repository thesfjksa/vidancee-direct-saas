## Viewer usability update — 10 November 2026

The initial interactive pilot connected but displayed a small, blurry ~1280x620 still and had no confirmation that a Windows click or typing action was actually executed. The new version includes:

- Screen capture up to **1600px** at JPEG quality up to **76** (previously 1280px / quality 44), with a host capture cadence of about **1 second**. The customer viewer polls around every 1.1 seconds, skips duplicate frames and decodes the next JPEG before swapping it in.
- **Fit**, **Actual size** (scroll/pan), **Theater**, and **Fullscreen** display modes. The viewer's mouse position uses the actual displayed image dimensions, not the surrounding padding.
- **Direct keyboard control**: click the remote AIVID webpage image to focus it; then type with the normal keyboard (input is batched), or compose a long prompt using the text field and Send text. Remote shortcuts are still restricted; no Ctrl+L, Alt+Tab, address bar or Windows key.
- **Verified native execution feedback**: each queued command has an ID. The Windows helper reports executed or blocked (for example, it lost AIVID foreground focus) via token-authenticated \`/api/aivid-native/host/ack\`. The CMMTools viewer distinguishes **Queued** from **Executed in Windows Edge** and shows rejection reasons, rather than claiming every queued action was successful. Only one controller remains authorized.
- **Scroll targeting**: Windows native helper moves the pointer into the center of the verified webpage rectangle before sending scroll-wheel input, so it doesn't scroll a different window.

**Upgrade:** redeploy the latest CMMTools web \`main\`, then download the **updated** Windows Host ZIP in Admin, extract/replace the earlier helper, close the old helper session, generate a fresh Admin pairing code, and launch the updated \`.cmd\`. Changes to the website alone are insufficient because the original Windows helper does not report input results and captures at lower resolution.

**Limits:** JPEG polling remains less fluid than actual RDP/WebRTC. Windows Edge UI Automation capture and native input still require a real RDP acceptance test. Do not grant customers access until that test succeeds in a dedicated standard Windows account. CMMTools can present the webpage without an address bar, but it cannot guarantee customers can never infer the provider's domain via content or outbound links.

# Native interactive Windows AIVID viewport in CMMTools — no URL bar, no Playwright

**Implementation:** opt-in experimental Windows-only pilot. The customer opens \`https://cmmtools.site/aivid-interactive-studio\` to see **only the AIVID webpage viewport** in a branded CMMTools viewer. The customer can click, enter prompts, scroll and activate Generate. The genuine browser remains **Microsoft Edge opened manually and signed in by the owner on Windows RDP**. The customer **does not receive the \`aivid.dev\` address bar or browser login cookies**. AIVID's logo/content may remain visible, as requested. No Playwright, Puppeteer, Chrome debugger, DOM scripts, browser extension injection, or Browserless is used for this *interactive viewer*.

This is **not** full Windows RDP, Apache Guacamole, or unrestricted remote desktop. It is an owner-run Win32 screen/input relay that reads the foreground Edge webpage-only rectangle using Windows UI Automation (or the explicit Chromium renderer child HWND). The helper never falls back to capturing an entire Edge window, address bar, or Windows desktop if no safe viewport rectangle can be found. Input uses OS-level Windows \`SendInput\` / \`mouse_event\` / \`keybd_event\` to that rectangle. Browser-only remote control is not the same as a formal security sandbox: overlapping UI, Edge changes and Windows account/session configuration remain security concerns.

## Setup — Windows RDP + existing CMMTools Hostinger web, no new VPS or Playwright

1. Deploy latest merged \`main\` to the existing Hostinger CMMTools **web** app. One Node web server instance (or sticky routing to one instance) is required; pairing/frame/input state is **memory only**, not shared between replicas.
2. **Create/use a dedicated standard Windows user account** with no administrator privileges, other apps, private data, browser logins, or saved passwords except the intended AIVID provider login. This helper explicitly refuses elevated administrator execution. The Windows session must stay **unlocked and interactive**. Do not run on the Windows administrator's ordinary desktop.
3. In that dedicated Windows account, open **Microsoft Edge normally**, visit \`https://aivid.dev/\`, sign in and complete any CAPTCHA **manually**. For a dedicated app window without an address bar, Edge offers **Settings and more (...) → More tools → Apps → Install this site as an app** (menu wording can vary). Name the app AIVID if prompted and open that installed app. Microsoft documents the menu in [Edge support](https://support.microsoft.com/en-us/edge/install-manage-or-uninstall-apps-in-microsoft-edge).
4. Visit **CMMTools Admin → Provider → Connections → AIVID → Windows Premium Studio**. Approve only the intended CMMTools user ID/email (up to three overall; only one actively controls this native session), tick the direct AIVID billing acknowledgment, and click **Save Windows Studio settings**. This is saved in the existing MySQL \`app_settings\` — no environment-variable toggles.
5. In the **Interactive Windows Host** section, click **Download Windows Host ZIP**. Extract it on the Windows RDP. It includes the inspectable source \`CMMTools-Remote.ps1\`, \`Start-CMMTools-Remote.cmd\`, and \`README.txt\`. No \`exe\` download or new Windows service required. Windows PowerShell 5.1 and .NET Framework are preinstalled on many supported Windows versions but must be available.
6. Click **Generate native host pairing code** in Admin (valid for 5 minutes). Double-click \`Start-CMMTools-Remote.cmd\` on Windows (not as Administrator). Paste the one-time code when prompted; it stays in process memory and the browser does **not** receive it.
7. Return focus to the **AIVID Edge app/window**. Leave it in the foreground. Other Windows dialogs, popups, locking the session or switching apps make the helper pause screenshot capture/input rather than exposing the desktop. A minimized/disconnected RDP session may also stop screen capture, depending on Windows graphics-session behavior.
8. The approved customer logs into CMMTools and opens \`https://cmmtools.site/aivid-interactive-studio\` (also linked from Video Studio). They can click in the screenshot, scroll, select text fields then use **Send text**, and use a small allowlist of safe keys. No Ctrl+L/Alt/Win/F11 browser or desktop navigation shortcuts are sent by the customer.
9. End access immediately in Admin using **Stop Windows Host**, or turn off Windows Studio and save, or close the Windows helper. A successful pairing expires absolutely after **90 minutes**, requiring a new Admin code.

## Security controls

- Web viewer requires **CMMTools login** and the existing Admin-saved allowed user ID/email, direct-billing acknowledgment and provider Sources permission *on every frame and action*. Same-origin checks block cross-site customer remote-control posts.
- **One remote controller** at a time, lease expires after one minute of inactivity; previous controller can voluntarily release it. Max 12 pending actions; 6-second queue TTL; constrained click coordinates, scroll delta, one text request up to 256 characters, safe keys only; no Ctrl, Alt, Win, F11, browser address-bar focus or arbitrary OS hotkeys.
- Host pairing is a **128-bit CSPRNG single-use code** with a 5-minute TTL and six attempts. This issues a 256-bit bearer token (server stores only SHA-256 digest), 90-minute absolute session. Host uses outbound HTTPS to CMMTools, not exposed Windows RDP ports. Token is kept in Windows PowerShell process memory and not written to any configuration file. Admin Stop revokes it immediately; Admin settings changes also revoke.
- Host only transmits **JPEG frames of a verified visible Edge Document/UI Automation or Chromium rendering child rectangle**, never browser chrome/URL bar or full desktop as a deliberate fallback. The selected foreground Edge window title must include **AIVID** and the process must be \`msedge\`. Captured frames are rechecked after capture and discarded on window switch. Native input is applied only while the same AIVID window is foreground. This is a best-effort restriction, not an OS-secure isolation boundary; topmost overlays within the captured area could still be visible. Keep the dedicated account empty and do not have other sensitive windows.
- Current frame (max 490 KiB JPEG, min 650ms between frames, stale after 12 seconds) and command queue live in a single Node web process memory. All HTTPS responses are \`no-store\`. No screenshots or passwords are stored in MySQL or public files.
- Only administrator requests behind the existing Admin token can download the host ZIP, generate a host pairing code or revoke a session. A new pairing replaces old one. Default disabled (existing Windows Studio setting).
- **Direct billing**: remote Generate uses the signed-in AIVID account and bypasses the CMMTools wallet/receipts. Therefore this is suitable **only for one explicitly trusted customer in a dedicated isolated Windows account**, with a provider-accepted delegation/white-label agreement. Enabling it may let that customer consume the provider balance.
- **No anti-bot guarantee**: Edge is manually opened with no Playwright debugging, but the provider might still present verification or detect OS-level remote inputs. Do not automate CAPTCHA solving or disable its protections.

## Important current limitations

- **No remote file-picker or MP4 transfer** in this pilot. The customer can click/select models, enter prompts and generate, but references selected from Windows dialogs and downloaded videos remain local to the Windows machine. Continue using an owner-operated, authorized file-delivery workflow for output until a safe transfer is implemented. This means the build is *interactive*, but **not yet complete end-to-end video delivery**.
- Native helper requires **interactive, unlocked Windows Edge**, a window title containing AIVID, and ability to locate its webpage rectangle via UI Automation or Chromium child HWND. Actual behavior depends on Windows version, graphics compositor, DPI scaling, Edge build and RDP behavior. **Windows acceptance testing is required** and not available to the assistant through GitHub.
- Installing the AIVID page as an Edge app gives a normal address-bar-free app window, but website links may open another Edge window or reveal origin inside page content. Our relay intentionally sends the webpage viewport only; it cannot guarantee the provider identity is hidden from a curious customer. The owner explicitly permits showing the AIVID logo.
- The separate existing paid-generation \`AIVID-Agent.exe\` STILL uses Playwright and has its own receipts, queues and automated sessions. This native interactive route **does not call that agent and does not remove its Playwright dependency**. Avoid starting new automatic paid AIVID submissions if you only want manual browser operation; do not interrupt any uncertain in-flight job.
